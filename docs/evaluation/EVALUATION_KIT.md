# User Acceptance and Evaluation Kit

Prepared November 25, 2026. Status: ready for stakeholder review; no respondent data has been collected by the coding agent. This is a draft evaluation aid, not a completed ISO certification or an invented evaluation result.

## Preparation

Have the adviser/program head approve the tasks, wording, respondent selection, consent process, scoring scale, and interpretation before evaluation. Use disposable test accounts and clearly identify the system version and test date. Keep personal identifiers out of published results.

## Role-based acceptance tasks

| Role | Task | Expected result | Result / comment |
|---|---|---|---|
| Student | Register using a new student number | Immediate student access without email or approval | |
| Student | Repeat registration with the same number | Duplicate is rejected without creating another account | |
| Student | Book an available consultation with a reason | Pending request with correct faculty/date/time | |
| Faculty | Approve/reject a booking | Student receives the decision and sees the status | |
| Student | Request a new time | Original booking remains until approval | |
| Faculty | Accept/decline the request | Acceptance changes the time after conflict checks; decline retains the old time | |
| Faculty / student | Faculty proposes a time; student responds | Other-party approval is required | |
| Faculty | Configure 30- or 45-minute appointments | Student choices match that duration | |
| Faculty | Block 10:00-11:00 only | Outside slots remain available | |
| Faculty | Edit hours that contain active bookings | Affected bookings are listed; no silent change | |
| Faculty | Navigate day/week/month views | Actual dates and non-hour starts display correctly | |
| Faculty | Cancel with a reason; mark an elapsed booking missed | Appropriate notification and retained record | |
| Both | Observe upcoming and starting-soon reminders | Each reminder appears once for the scheduled time | |
| Admin | Search/filter records and export CSV | Matching records include cancelled and missed entries, across pages | |
| Student / faculty | Try another user's protected record | Access denied | |
| All | Use a phone-sized viewport and keyboard | Primary flows remain usable and readable | |

Record each result as Pass, Fail or Not Tested; include reproduction steps and issue severity. Retest fixes. Automated tests supplement these tasks but do not replace stakeholder acceptance or camera/mobile checks.

## Draft questionnaire

Use the institution-approved response scale. If approved, a four-point agreement scale can be used: 1 Strongly Disagree, 2 Disagree, 3 Agree, 4 Strongly Agree. The source paper states a target evaluation rating of at least 2.50; the adviser should approve how that threshold is calculated and interpreted for the final instrument.

| Area | Draft statement | Rating | Comment |
|---|---|---|---|
| Functional suitability | The system lets me complete the consultation tasks needed for my role. | | |
| Scheduling correctness | Available slots, durations, blocks, and appointment dates are accurate. | | |
| Conflict handling | The system prevents conflicting bookings and explains why a change cannot be saved. | | |
| Interaction and clarity | Navigation, labels, status messages and controls are easy to understand. | | |
| Rescheduling | It is clear which time is currently reserved and whether a change needs my response. | | |
| Accessibility and mobile use | I can read and operate the main screens on the devices I use. | | |
| Performance | Pages and booking responses appear within an acceptable time. | | |
| Reliability | My saved bookings and history remain consistent after refreshing or signing in again. | | |
| Security and privacy | I can access the records appropriate to my role without seeing unauthorized records. | | |
| Notifications | Decisions, reminders and changes reach me clearly within the system. | | |
| Overall acceptance | I would use the system for consultation scheduling. | | |

These statements are proposed research questions. Map them to the final quality characteristics and approved questionnaire in the capstone methodology; do not label the draft as an official ISO questionnaire.
